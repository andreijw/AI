# AI Reinforcement Learning Framework — Manual Testing Manual (`TESTING.md`)

This document outlines manual verification and testing procedures for the RL framework.

---

## 1. Environment & Feature Demonstrations

### Gymnasium Feature Sanity Check

- **Script**: `examples/demo_env_features.py`
- **Purpose**: Verify that observation noise, action flip noise, domain randomization, and vectorized environments
  execute without crashes or numerical errors.

| Check # | Target Feature | Steps to Execute | Expected Behavior |
| --- | --- | --- | --- |
| ENV-1 | **Standard Environment** | `python examples/demo_env_features.py` | Runs demo 1 cleanly; CartPole resets and takes random steps. |
| ENV-2 | **Observation Noise** | Observe demo 2 console output. | Adds Gaussian noise to observations; state values deviate slightly from raw dynamics. |
| ENV-3 | **Action Noise** | Observe demo 3 console output. | Actions flip stochastically based on specified probability without throwing errors. |
| ENV-4 | **Domain Randomization** | Observe demo 4 console output. | Physical parameters (`gravity`, `masscart`, `masspole`, `length`) resample per episode. |
| ENV-5 | **Vectorized Execution** | Observe demo 5 console output. | Runs 4 parallel vectorized environments; step returns batched arrays with shape `(4, 4)`. |
| ENV-6 | **Box2D for LunarLander and BipedalWalker** | `./setup.sh` (or the manual steps in docs/usage.md, LunarLander (Box2D)), then `.venv/bin/python -c "import gymnasium as gym; gym.make('LunarLander-v3').reset(seed=0)"` | setup.sh builds `box2d-py` 2.3.8 (about 95 seconds), prints `Box2D 2.3.8`, and the LunarLander and BipedalWalker tests run instead of skipping. Without it, building any of Gymnasium's Box2D environments through a challenge (LunarLander-v3, LunarLanderContinuous-v3, BipedalWalker-v3) raises an `ImportError` naming the environment, `./setup.sh` and the manual steps: `BaseEnvWrapper._make_env` checks before `gym.make`. |
| ENV-7 | **Velocity Masking and Frame Stacking** | `python -c "from rl_cartpole.environments import make_env; e = make_env(seed=0, mask_velocity=True, frame_stack=4); o, _ = e.reset(); o, *_ = e.step(0); print(o.shape, o[1::2])"` | Prints `(16,)` and eight zeros: four stacked CartPole frames, each with its cart and pole velocities masked. The same keys in any config's `environment` section work for every challenge (`frame_stack: 4`, `mask_velocity: true`); an environment id the wrapper has no velocity layout for is refused naming `mask_velocity` (Navigation-v0 and NavigationContinuous-v0, whose observation holds no velocity of the robot, and BipedalWalker-v3, whose wrapper lists no velocity entries). |
| ENV-8 | **Navigation without the framework** | `python -c "import sys, gymnasium as gym, rl_navigation.gym_env; e = gym.make('NavigationContinuous-v0'); o, _ = e.reset(seed=0); o, r, term, trunc, info = e.step(e.action_space.sample()); print(o.shape, e.spec.max_episode_steps, sorted(info), 'rl_core' in sys.modules)"` | Prints `(10,) 400 ['collision', 'goal_distance', 'is_success'] False`: five goal and command entries and five sonar readings, the 400-step limit, and no `rl_core` loaded. `gym.make('Navigation-v0')` has `Discrete(5)` actions. |
